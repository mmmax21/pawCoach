# PawCoach MVP 开发计划（Hackathon 版，最小技术验证顺序）

> 依据：[research.md](research.md) 第三节「MVP 技术路线建议」。
> 背景：本项目用于参加 Hackathon，**不做商业化**，只使用公开数据源。
> 原则：**先验证风险最高、最可能失败的技术假设，再搭演示外壳**。每个阶段有明确的通过标准，不通过就走降级方案，保证比赛当天一定有可演示的结果。

---

## 0. MVP 范围

**只做一个场景：「坐下 + 等待（Sit-Stay）」**。

输入：一段 20～60 秒的训练视频（狗全身入镜，最好能听到口令）。
输出：

1. 本段视频的结构化记录：每一轮「口令 → 坐下 → 保持 → 中断 / 奖励」的时间点；
2. 指标：反应延迟、保持时长、中断次数、奖励延迟；
3. 和历史记录对比的进度判断；
4. 下一次练习计划（目标时长、次数、要改正的一个动作）；
5. 风险提示（检测到恐惧 / 攻击迹象或厌恶式方法时，建议找专业人员）。

**不做**：实时视频、牵绳 / 定点排泄等其他场景、原生 App、账号与支付、训犬师后台。

### 核心指标定义

| 指标 | 定义 | 依据 |
|---|---|---|
| 反应延迟 | 口令出现 → 狗进入「坐」姿态的秒数 | 口令时间戳 + 姿态时间线 |
| 保持时长 | 进入「坐」→ 离开「坐」或被释放的秒数 | 姿态时间线 |
| 中断次数 | 每轮里未经释放就起身的次数 | 姿态时间线 |
| 奖励延迟 | 目标行为发生 → 标记词 / 递零食的秒数，> 1 秒判为「偏晚」 | 标记词时间戳 / 手部动作 |
| 成功率 | 达到当日目标时长的轮次 / 总轮次 | 汇总 |

## 1. 公开数据源

### 1.1 训练与评估用数据集

| 数据 | 用在哪个阶段 | 用途 | 获取 |
|---|---|---|---|
| **DogPoseCV** | P1 | 「坐 / 站 / 卧」图像分类器的训练数据（20,578 张，免申请） | https://huggingface.co/datasets/stockeh/dog-pose-cv |
| **APT-36K** | P1 | 带关键点和跟踪 ID 的动物视频，从中筛出狗的片段，评估跨帧跟踪和姿态时间线 | https://github.com/pandorgan/APT-36K |
| **Animal Kingdom** | P1（可选） | 带动作标注的动物视频，可补充狗「坐下 / 躺下」等动作片段 | https://github.com/sutdcv/Animal-Kingdom （需申请，来不及就跳过） |
| **StanfordExtra** | P1（可选） | 狗的 2D 关键点，用于检查关键点规则方案 | https://github.com/benjiebob/StanfordExtra （需申请，来不及就跳过） |
| **DeepLabCut SuperAnimal-Quadruped** | P1 | 预训练四足动物关键点模型，直接推理，无需训练 | https://huggingface.co/mwmathis/DeepLabCutModelZoo-SuperAnimal-Quadruped |

### 1.2 「人 + 狗训练过程」视频（用于端到端评估和演示）

公开数据集里**没有**带口令和奖励标注的人犬训练视频，所以从公开视频平台收集真实训练片段，自己标注时间点：

| 来源 | 特点 | 许可 |
|---|---|---|
| **YouTube 上的 Creative Commons 视频** | 训犬教程最多，**带口令声音和递零食动作**，是 P2～P4 的主要评估来源。搜索时用「筛选 → 特征 → 知识共享」，关键词如 `dog sit stay training`、`狗狗 等待 训练` | CC BY，需在演示和文档中注明作者和链接 |
| **Pexels / Pixabay 免费视频** | 画质好，多为狗坐下、趴下的空镜，**通常没有口令声音**，主要用于 P1 姿态评估 | 平台自有免费许可，允许免费使用和修改，无需署名（署名更好） |
| **Wikimedia Commons** | 数量少，可补充 | 各文件单独标注的自由许可 |

收集规则：

- 只用明确标注 CC 或平台免费许可的视频，在 `data/sources.csv` 记录每段的链接、作者、许可和截取的时间段；
- 截成 20～60 秒片段，目标 **≥ 20 段**：其中 ≥ 10 段带口令声音（YouTube CC），其余为无声的姿态片段；
- 尽量覆盖不同犬种 / 毛色、室内外、横竖屏、狗中途起身的情况。

> **可选**：团队成员如果有狗，可以按拍摄规范自拍几段作为比赛现场演示素材，但开发和评估不依赖它。

## 2. 验证顺序总览

| 阶段 | 要验证的假设 | 风险 | 预估工作量 | 通过标准 |
|---|---|---|---|---|
| **P0** 评估数据 | 能从公开来源收集到足够多可用的训练视频，并完成标注 | 中 | 1 天 | ≥ 20 段视频，人工标注完成 |
| **P1** 狗姿态时间线 | 能从视频稳定算出「坐」的起止时间 | **最高** | 2～3 天 | 保持时长误差 ≤ 1 秒的片段 ≥ 80% |
| **P2** 口令识别 | 能从音频找到「坐 / 等 / 好」或 sit / stay / good 的时间点 | 中 | 1 天 | 口令召回率 ≥ 90%，时间误差 ≤ 0.5 秒 |
| **P3** 奖励时机 | 能判断奖励给得早 / 准 / 晚 | 高 | 1～2 天 | 奖励时间误差 ≤ 0.5 秒的事件 ≥ 70%；否则启用降级方案 |
| **P4** 事件对齐与指标 | 三条时间线能合成正确的「轮次」 | 低 | 1 天 | 轮次切分与人工标注一致率 ≥ 85% |
| **P5** 进度追踪与计划生成 | 规则 + 大模型能给出合理、安全的下一次计划 | 中 | 1～2 天 | 自评 ≥ 80% 计划合理，安全用例 100% 正确转介 |
| **P6** 演示原型 | 评委能上传视频并看到结果和进度曲线 | 低 | 1～2 天 | 60 秒视频 3 分钟内出结果 |
| **P7** 比赛准备 | 演示稳定、讲得清楚 | 低 | 1 天 | 完整彩排 2 次无故障 |

> 工作量按 1 名工程师估算，合计约 9～13 天；多人时 P1、P2/P3 可并行。P1 不通过时要先停下来走降级方案。

## 3. 各阶段详细计划

### P0：收集并标注评估数据

- **收集**：按 1.2 节规则从 YouTube CC、Pexels、Pixabay 收集片段，记录来源和许可。
- **标注**：用 [ELAN](https://archive.mpi.nl/tla/elan) 或 [Label Studio](https://labelstud.io/) 的视频时间轴标注，导出为 JSON。每段标注：
  - `cue`：口令文字与时间点
  - `pose`：坐 / 站 / 卧 / 看不清 的时间区间
  - `marker`：标记词（「好」「对」「good」「yes」）时间点
  - `reward`：递零食到狗嘴边的时间点
  - `release`：释放口令时间点
- **一致性检查**：抽 5 段由两人分别标注，时间点差异 > 0.5 秒的条目讨论统一标准，写进 `data/annotation_guide.md`。
- **说明**：公开视频多为英文教程，P2 需要同时支持中英文口令。

**产出**：`data/raw/*.mp4`、`data/labels/*.json`、`data/sources.csv`、`data/annotation_guide.md`

### P1：狗姿态时间线（风险最高，最先做）

目标：输入视频 → 输出每一帧（下采样到 10 fps）的姿态和置信度 → 平滑成「坐」的时间区间。

并行试三种方案，在 P0 视频和 APT-36K 狗片段上对比：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 关键点 + 规则** | SuperAnimal-Quadruped 提取关键点 → 用臀部、膝盖、肩部的相对高度和角度写规则判断「坐」 | 不需要训练，可解释 | 对遮挡、长毛犬、侧拍角度敏感 |
| **B. 图像分类器** | 在 DogPoseCV 上微调轻量模型（如 MobileNetV3 / EfficientNet-B0），输入用检测框裁剪出的狗 | 实现简单，速度快 | DogPoseCV 是静态网图，和视频帧有差别 |
| **C. 视频大模型零样本** | 把抽帧图片交给多模态大模型，直接问每秒的姿态 | 最快出结果，作对照基线 | 成本高、时间精度差，Martvel et al. 2025 表明可靠性有限 |

流程：

1. 狗检测与跟踪：用 YOLO 系列检测 `dog` 类别，按 IoU 关联跨帧，只保留主要那只狗。
2. 姿态判断：方案 A / B / C 各自输出逐帧标签。
3. 时序平滑：滑动窗口多数投票 + 最短持续时间（如 < 0.5 秒的抖动丢弃），得到区间。
4. 质量门槛：狗不在画面里或置信度低的片段标为「看不清」，不参与指标计算。

评估（对比 P0 人工标注）：逐帧准确率、「坐」区间起止时间误差、保持时长误差。

**通过**：最佳方案保持时长误差 ≤ 1 秒的片段 ≥ 80%。
**不通过时**：先把 A、B 两个方案的结果融合；仍不行，从 P0 视频和 Pexels / Pixabay 视频中抽 500～1000 帧标注后微调方案 B；再不行，演示改为「用户在视频上手动点选坐下的开始 / 结束，系统只做统计和计划」。

**产出**：`pawcoach/pose/`、`notebooks/p1_pose_eval.ipynb`、`reports/p1.md`

### P2：口令与标记词识别

1. 用 ffmpeg 提取 16 kHz 单声道音频。
2. 中文用 FunASR（Paraformer + 时间戳），把「坐、等、等等、好、对、可以了」设为热词；英文用 Whisper（词级时间戳），口令词为 sit / stay / wait / good / yes / okay / free。
3. 关键词匹配 + 同义词表（用户可自定义口令词），输出 `cue / marker / release` 事件。

**通过**：口令召回率 ≥ 90%，时间误差 ≤ 0.5 秒。
**不通过时**：让用户在上传时填写自己用的口令词，缩小匹配范围；或改用短关键词检测模型。

**产出**：`pawcoach/audio/`、`reports/p2.md`

### P3：奖励时机

分两条路验证：

- **标记词作为奖励信号**（优先）：P2 已经能拿到时间点，误差最小。
- **递零食动作**：MediaPipe Hands / Pose 跟踪训练者的手，判断「手从身体移向狗头附近」的时刻；结合狗头关键点距离。

**通过**：奖励时间误差 ≤ 0.5 秒的事件 ≥ 70%。
**降级方案**：只按标记词计算奖励时机，递零食识别留到比赛之后。

**产出**：`pawcoach/reward/`、`reports/p3.md`

### P4：事件对齐与指标计算

把三条时间线合成「轮次」：

```
轮次 = 一次 cue("坐") → 狗进入坐姿 → [保持] → release / 起身 / marker+reward
```

- 规则引擎实现，不用模型；每一轮输出反应延迟、保持时长、是否中断、奖励延迟。
- 无法配对的事件（有口令无动作、动作无口令）单独记录，作为反馈素材（例如「口令重复了 3 遍狗才坐」）。
- 数据结构（单段视频的结果）：

```json
{
  "video_id": "…",
  "dog_id": "…",
  "date": "2026-11-14",
  "quality": {"dog_visible_ratio": 0.93, "audio_ok": true},
  "trials": [
    {"cue_t": 2.1, "sit_start": 3.0, "sit_end": 9.4, "ended_by": "release",
     "reward_t": 9.8, "latency": 0.9, "hold": 6.4, "reward_delay": 0.4}
  ],
  "summary": {"trials": 4, "success_rate": 0.75, "median_hold": 6.1}
}
```

**通过**：轮次切分与人工标注一致率 ≥ 85%。

**产出**：`pawcoach/events/`、`pawcoach/schema.py`、单元测试

### P5：进度追踪与下一次练习计划

分三层，**规则决定数字，大模型只负责解释**：

1. **规则层**（确定性、可测试），参照常见的逐步加时长做法：
   - 最近 2 次成功率 ≥ 80% → 目标时长 +20～30%；
   - 成功率 < 50% → 目标时长回退到上一档；
   - 奖励偏晚占比 > 30% → 本次重点改为「标记时机」，时长不加；
   - 每次训练 3～5 分钟、5～10 轮（参考 Demant et al. 2011 关于训练频率与时长的研究）。
2. **大模型层**：输入本次指标、历史趋势、规则层输出的计划，生成中文反馈：做得好的一点、最需要改的一点、下一次具体怎么练。要求引用视频时间点（例如「第 12 秒狗起身前你已经在走开」）。
3. **安全层**（硬规则，优先于以上所有输出）：
   - 用户文字描述或大模型识别到咆哮、龇牙、扑咬、明显恐惧（夹尾、缩身、躲避）→ 不给训练计划，建议联系专业行为人员；
   - 识别到打、踢、猛拉牵绳等厌恶式方法 → 温和提醒，并说明原因（参考 Vieira de Castro et al. 2020）。

**多日进度数据**：公开视频没有同一只狗连续多天的记录，演示用以下方式构造：

- 把同一频道、同一只狗的多段视频按发布时间排成「第 1 天、第 2 天……」；
- 不够时，用 P4 的真实单段结果为起点，按规则模拟后续几天的指标，并在演示中明确标注为模拟数据。

评估：准备 30 个情景用例（含 5 个安全用例），团队交叉评审；有条件的话请 1 位训犬师看一遍。

**通过**：≥ 80% 计划被评为合理，安全用例 100% 正确转介。

**产出**：`pawcoach/coach/`、`prompts/`、`eval/coach_cases.yaml`、`reports/p5.md`

### P6：演示原型

- **后端**：Python + FastAPI；任务用后台线程，不引入消息队列；存储用 SQLite + 本地文件。
- **前端**：一个移动端网页，三个页面：上传视频、本次结果（视频时间轴 + 指标 + 反馈）、进度曲线。
- **性能目标**：60 秒视频 3 分钟内出结果。比赛现场网络不稳定时，预先跑好几段视频的结果作为备用。

**产出**：`app/`、`web/`、启动说明

### P7：比赛准备

- 选 3 段效果最好的视频作为现场演示，另备 1 段「检测到恐惧信号 → 转介」的安全演示；
- 准备一页准确率报告：P1～P4 各项指标在公开评估集上的结果，说明数据来源和局限；
- 在演示页和 README 里列出所有使用的数据集、视频来源和许可（满足 CC BY 署名要求）；
- 完整彩排 2 次。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 姿态识别在真实视频上不准 | 核心指标失效 | P1 降级路径：方案融合 → 抽帧微调 → 手动打点 |
| 公开视频里带口令声音的训练片段不够 | P2～P4 评估样本少 | 扩大关键词（中英文、不同口令）；不够时团队自拍补充 |
| 公开视频有背景音乐、剪辑和旁白 | 口令识别和时间线被打断 | 优先选一镜到底、无背景音乐的片段；剪辑点处切成不同片段 |
| 奖励动作识别不可靠 | 无法评价时机 | 只按标记词计算 |
| 没有同一只狗的连续多日数据 | 无法真实展示进度 | 同频道视频按时间排序；不够时用模拟数据并明确标注 |
| 大模型给出不安全建议 | 演示出现错误建议 | 规则层决定计划数字，安全层硬拦截 |
| 数据许可与署名 | 比赛合规 | 只用公开许可来源，在 `data/sources.csv` 记录，演示中注明来源 |

## 6. 第一周行动清单

1. 下载 DogPoseCV、APT-36K，申请 Animal Kingdom 和 StanfordExtra（不等结果，先往下做）。
2. 从 YouTube CC、Pexels、Pixabay 收集首批 20 段视频，建立 `data/sources.csv`。
3. 搭好 Python 项目骨架、ffmpeg 抽帧和视频质量检查。
4. 跑通 SuperAnimal-Quadruped 对样例视频的推理，输出关键点可视化。
5. 在 DogPoseCV 上训练第一个「坐 / 站 / 卧」分类基线。
6. 跑通 FunASR（中文）和 Whisper（英文）带时间戳的转写，测试口令词效果。
7. 周末：完成 P0 标注和 P1 首轮对比，决定姿态方案。
