# D2 性能优化（降帧 10fps）+ 跑通 + 记基线

- 预计工时：1～2h
- 验收命令：
  ```bash
  # 删缓存后计时完整全流程（转码 + 推理 + 检测 + LLM）
  rm -f data/pose/dog3.norm* data/normalized/dog3.norm.mp4
  time .venv-b/bin/python -m pawcoach.cli analyze data/raw/dog3.mp4
  # 期望：≤ 3 分钟
  ```
- 验收结果：**通过**（dog3 55.5s 视频全流程 **1m34s**）

## 做了什么

1. **降采样帧率 30 → 10fps**（`normalize.py` 的 `TARGET_FPS`）：Sit-Stay 姿态是秒级变化，10fps（0.1s 一帧）足够捕捉坐/站/卧切换。帧数降到 1/3，SuperAnimal 推理和 YOLO 检测都快 3 倍。
2. **缓存键与转码产物对齐**：降帧后 30fps 视频（如 dog3）会被转码成 `dog3.norm.mp4`，推理/检测在这个产物上跑，deeplabcut 按 `dog3.norm` 命名输出，`find_h5`/`track_path` 的缓存键就是转码产物名（不用剥 `.norm`；`asr` 剥 `.norm` 是对的，因为 whisper 转写的是原始视频的音频、与帧率无关）。
3. **缓存缺失自动推理**（`run_if_missing=False → True`）：降帧后推理约 80s，analyze 里隐式跑可接受（30fps 时要 4.5 分钟，必须报错）。
4. 更新 `test_normalize.py` 5 处 30fps 断言 → 10fps。

## 验收证据

- dog3（55.5s，30fps → 10fps 转码后 555 帧）删缓存后完整全流程计时 **real 1m34.266s**（含转码 + SuperAnimal 推理 + YOLO 检测 + LLM）。按比例 60s 视频 ≈ 102s，远低于 3 分钟目标。
- 输出正确：姿态真实现、LLM 引用时间点（11s/26s/39.1s/50.5s…）、规则层 focus=「标记时机」命中。
- 单测 **83 passed**。

## 基线（对比）

| 项 | 降帧前 | 降帧后 |
|---|---|---|
| 推理帧率 | 30fps | 10fps |
| 60s 视频帧数 | 1800 | 600 |
| 姿态推理耗时 | ~4.5 分钟（4.5 倍实时） | ~80s |
| dog3（55.5s）全流程 | 无法在 3 分钟内（推理就超） | **1m34s** |

## 遗留

1. **dog3 是 55.5s 不是精确 60s**（仓库没有精确 60s 的干净视频），用 55.5s 按比例外推 60s ≈ 102s。
2. **10fps 对极快动作（瞬间扑咬、猛拉）可能不够**——但 Sit-Stay 是秒级场景，够用；安全层靠 `red_flags` 用户勾选兜底，不靠姿态捕捉快速动作。
3. 转码导致缓存键从 `dog3` 变成 `dog3.norm`，旧缓存已删、新缓存按转码产物名重建；未来所有 30fps 视频都会转码到 10fps，缓存键统一为 `.norm`。
4. `asr`（剥 `.norm`）与 `pose/detect`（不剥）的缓存键不对称，是合理的（音频与帧率无关、姿态与帧率相关），但容易让读者困惑，已在代码注释说明。
