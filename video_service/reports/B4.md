# B4 姿态换真 + 跑通 + 记基线

- 预计工时：1～2h
- 验收命令：
  ```bash
  .venv-b/bin/python -m pawcoach.cli analyze data/raw/dog3.mp4 -o results/dog3.json   # 真姿态
  .venv-b/bin/python -m pawcoach.cli analyze data/raw/dog2.mp4 -o results/dog2.json   # 正面视角
  .venv-b/bin/python -m pawcoach.cli analyze data/raw/sample.mp4 -o results/sample.json
  .venv/bin/python   -m pawcoach.cli analyze data/raw/sample.mp4 -o results/sample.json  # 回退 stub
  .venv/bin/python -m pytest -q
  ```
- 验收结果：**通过**
  - `.venv-b` 里 `analyze` 用 SuperAnimal 真实现（打印 `[姿态：superanimal]`），`.venv` 里自动回退 stub（打印 `[姿态：stub…]`）。
  - dog3：1 轮，`sit_start=1.83s`、`sit_end=7.47s`、`hold=5.63s`、`ended_by=stand_up`，另 3 段坐进 `unpaired`（`sit_without_cue`）。肉眼核对：狗在 1.8 秒左右坐下，和标注的坐姿起点对得上，符合计划「时间轴大致对得上到 1 秒内」。
  - dog2：0 轮（正面视角全降级 `unclear`，B2 已知行为），`unpaired=[cue_without_sit]`。
  - sample（无狗）：0 轮。
  - 35 个单测全过。
- 基线指标（dog3 第一段坐，人工标注为参照）：

  | 字段 | 值 | 说明 |
  |---|---|---|
  | sit_start | 1.83s | 狗开始坐下，画面里 1.8s 前后 |
  | sit_end | 7.47s | 狗起身，画面里 7.4s 前后 |
  | hold | 5.63s | 与肉眼看视频一致到 1 秒内（粗略） |
  | latency | 1.83s | stub 口令 cue_t=0.0，所以等于 sit_start，不是真实口令反应时 |
  | conf | 0.55 | 这一段关键点平均置信度 |

  `hold=5.63s` 是「姿态线给出的保持时长」，不是「训练目标达成的时长」。stub 口令的 cue 在 0 秒，marker/release 在视频末尾，所以 ended_by 是 stand_up 而不是 release。
- 实现（`pawcoach/cli.py`）：
  - 新增 `_make_pose_extractor()`：环境里能 `import pandas`（读 SuperAnimal H5 需要）就返回 `SuperAnimalPoseExtractor(run_if_missing=False, use_detection=True)`，否则回退 `StubPoseExtractor`。两个分支都打印，跑的时候能一眼看出用的是哪个。
  - 姿态推理和狗检测**只读缓存**（`run_if_missing=False`），缓存缺失时明确报错，不在 `analyze` 里隐式跑模型。跑模型是 B1/B3 的脚本负责的，`analyze` 保持「快、确定性、一条命令」。
  - 编排代码没动，`align` 到落库都不变——这验证了 A4 的 Protocol 设计：换实现只改注册处。
- 两个 Python 环境（已知问题 9 的落地方案）：
  - `.venv-b`（3.12）有 pandas/ultralytics/deeplabcut，能完整跑 `analyze` 真姿态。
  - `.venv`（3.13）只有 numpy/pydantic/httpx，读 H5 会 `ImportError`，所以回退 stub。
  - 目前没做「子进程自动调 `.venv-b`」，也就是在 `.venv` 里跑 `analyze` 得到的是 stub 结果，不是真姿态。要在 `.venv` 里也得到真姿态，用 `.venv-b/bin/python` 跑即可。子进程方案留到后面需要时再做（见遗留问题）。
- 遗留问题：
  1. **缓存按视频文件名匹配，和「分析前先标准化」有冲突。** `analyze` 先调 `normalize_video`，对 HEVC 视频（如 `dog1.mp4`）会转码成 `data/normalized/dog1.norm.mp4`，此时 `SuperAnimalPoseExtractor` 会按 `dog1.norm` 找 H5 和 dogbox，而 B1/B3 的缓存是按原始名 `dog1` 存的，找不到就报错。dog2/dog3/sample 都是 h264+30fps+rotation0，`normalize_video` 原样复用、路径不变，所以没踩到。**这一步的正确做法还没定**：关键点和检测框到底该对「原始视频」跑还是对「标准化后视频」跑（标准化会缩放、摆正、改帧率，坐标和帧数都会变），要在后面 B5～B8 或换新视频时决定，并让缓存键跟随决定一致。这也是已知问题 14 的具体化。
  2. **新视频要先用 B1/B3 脚本跑出缓存**，`analyze` 才能用真姿态。没有缓存的视频（如 dog1）在 `.venv-b` 里跑 `analyze` 会报「找不到 H5」。报错信息目前是 `FileNotFoundError`，够明确但没有「先跑哪个脚本」的提示。
  3. `.venv` 里 `analyze` 静默回退 stub，只有一行 `[姿态：stub…]` 提示。如果用户没注意到，会以为拿到了真姿态结果。后续要么让 `.venv` 也能跑真姿态（子进程调 `.venv-b`），要么把回退做得更显眼（比如在结果 JSON 里记一个 `pose_impl` 字段）。
  4. `quality.dog_visible_ratio` 仍是写死的 1.0。现在有 B3 的狗检测了，本可以算成「狗在画面的帧占比」，但这一步没接，留作后续。
  5. `analyze` 默认输出文件名按原始 `video_id`（`dog3`）定，不按标准化产物名，这个之前已经处理好了，没有回归。
