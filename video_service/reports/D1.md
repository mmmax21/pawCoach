# D1 FastAPI 后端 + 接口契约 + 跑通 + 记基线

- 预计工时：2～3h
- 验收命令：
  ```bash
  .venv/bin/python -m uvicorn app.main:app --port 8001
  curl -F "file=@data/raw/sample.mp4" -F "meta=<data/raw/sample.meta.json" localhost:8001/analyze
  # 期望：返回 job_id，稍后 GET /results/<id> 拿到 JSON
  ```
- 验收结果：**通过**

## 做了什么

1. **抽 `analyze_video` 到 `pawcoach/analyze.py`**：把 `_cmd_analyze` 的编排（标准化→meta→三条流水线→align→聚合→coach→落库）抽成可复用函数，cli 和 app 后端共用。辅助函数 `_make_pose_extractor`/`_median`/`_success_rate`/`_dog_visible_ratio` 一并移过去；`cli.py` 的 `_cmd_analyze` 精简为「调 analyze_video + 写 JSON + 打印」。
2. `schema.py` 加 `meta_from_dict()`（app 上传的 meta 是 JSON 字符串，需要解析入口）。
3. `app/main.py`（FastAPI）：
   - `POST /analyze`：multipart 上传 `file`（视频）+ `meta`（可选 JSON 字符串）→ 后台线程跑 `analyze_video` → 返回 `job_id`。
   - `GET /results/<job_id>`：`pending` / `done`（完整 result）/ `failed`。
   - `GET /`：健康检查。
   - 接口契约写进 docstring + `app/README.md`。
4. `requirements.txt` 加 `fastapi` / `uvicorn` / `python-multipart`。

## 验收证据

- 健康检查 `{"status":"ok"}`；上传返回 `{"job_id":"10279d09...","status":"pending"}`；轮询后 `{"status":"done","result":{...}}`，result 含完整 `quality/trials/summary/unpaired/coach`，coach 是 LLM 真实调用的大白话建议。
- 单测 **83 passed**（原 81 + 新增 2：`test_app.py` 健康检查 + 404）。

## 遗留

1. **job 状态存内存**（`_JOBS` dict），进程重启即失，无持久化。MVP 够用，比赛现场若重启会丢在跑的任务。
2. **上传的视频 `video_id` 带 job_id 前缀**（`{job_id}_{文件名}`），是为了避免重名冲突，但比「干净 video_id」丑一点。
3. **上传文件不清理**，`data/uploads/` 会随上传增长（`data/` 已在 `.gitignore`）。
4. **本机 8000 被 Docker（Attu/Milvus）占用**，所以默认用 8001；前端对接时端口要约定清楚。
5. 姿态在 `.venv` 是 stub（缺 pandas），要真姿态得用 `.venv-b` 起服务。
