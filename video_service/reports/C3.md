## 做了什么

1. **`target_hold` 来源定了**（C2 遗留的前置决策）：`meta.json` 加可选字段 `target_hold`（目标保持时长），因为目标是用户的**训练意图**、不该由系统猜。字段带进 `AnalysisResult` 存进 results JSON，history 里也能读到。
2. `rules.py` 加 `effective_target_hold()`（meta 没填 → 回退 median_hold → 回退 10s）和 `sop_query_terms()`（从 `ProgressPlan` 构造 SOP 检索词）。
3. **SOP 语料 + 检索**：`prompts/sop.md`（Sit-Stay 分级 SOP：3 秒→10 秒→加干扰 + 常见错误）+ `coach/sop.py` 关键词命中打分，取 top_k 章节，不上向量库。
4. **`LLMCoach` 升级**：prompt 注入「本次指标 + 历史趋势（最近 3 次）+ 规则层输出 + 检索到的 SOP」，要求三点建议各自引用时间点。
5. **`TemplateCoach` 升级**（本机无 key，验收走这条兜底）：输出「✅ 做得好的 / ⚠️ 最需改 / 📋 下次怎么练」，引用 `cue_t` / `reward_t` 时间点，尾部接规则层目标时长 + 频率。

## 验收证据

- 单测 **66 passed**（原 59 + 新增 7：`test_sop.py` 5 个、`test_template.py` 2 个）。
- dog3 端到端（无 `LLM_API_KEY`，走 TemplateCoach 兜底）：

  ⚠️ 最需改：第 1 轮奖励给晚了 11.2 秒（13.0s 才递零食），狗会把「起身」和奖励联系起来，下次坐下后 1 秒内标记。
  📋 下次目标保持 7.6 秒。每次 3～5 分钟、5～10 轮，每周 1～2 次（不要每天练）。

  引用了 `11.0s` / `13.0s` / `0.80` / `11.2` 多个时间点，满足「引用到具体秒数」。

- SOP 检索冒烟（晚奖励场景 → 检索词 `[保持, 奖励, 标记, 零食, 晚]`）：命中「入门：3 秒保持」（含「零食必须在坐下后 1 秒内给，晚了狗会以为奖励是因为起身」）和「巩固：10 秒保持」。

## 遗留

1. **关键词检索会把通用词（保持/奖励/标记）刷高的章节排前面**，晚奖励场景下最贴题的「常见错误」章节（只含「奖励」「晚」两词）分数反而低、可能掉出 top_k。这是「简单关键词检索」的固有精度，C3 原文明确不上向量库；要更准得加 IDF 权重或换 embedding，留以后。
2. **LLMCoach 真实 API 调用仍未验证**（本机无 `LLM_API_KEY`），只验证了兜底分支 + `_build_prompt` 的注入结构。有 key 后要跑一次看 prompt 是否按预期生成。
3. 历史趋势只注入最近 3 次，多日数据本就没有（B 阶段已知问题），规则层「最近 2 次成功率」实际只有本次，第一次训练不升档。
