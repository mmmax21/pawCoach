# A10 视频标准化（手机 HEVC / 竖屏旋转 / 变帧率）

- 预计工时：1～1.5h
- 背景：目标平台是安卓和 iOS，输入是手机视频。iPhone 默认 HEVC `.mov`，竖拍靠旋转元数据标方向，帧率常为可变。放在 B1 之前，避免姿态推理拿到方向错误或编码不兼容的画面。
- 验收命令：
  ```bash
  source .venv/bin/activate
  python -m pawcoach.cli probe <手机视频>
  python -m pawcoach.cli normalize <手机视频>
  python -m pytest tests/ -q
  ```
- 验收结果：**通过**
  - 用合成素材模拟 iPhone 视频（HEVC + 旋转标记 + 变帧率）：`probe` 识别出 `codec=hevc, rotation=270, vfr=True`；`normalize` 列出三条转码原因，输出 `codec=h264, rotation=0, vfr=False, fps=30.00`，尺寸从 320x180 变为 180x320。
  - 对比抽出的画面：标准化输出的方向和尺寸与播放器按旋转标记显示的一致。
  - `analyze` 接入标准化：对旋转 HEVC 素材跑通，先打印标准化原因，再出结果；对 `sample.mp4`、`dog2.mp4` 这类已符合标准的视频原样复用，不转码。
  - `tests/` 共 12 个用例通过（新增 10 个：判断逻辑 8 个、端到端 2 个）。
- 基线指标：无（本步骤无模型）
- 遗留问题：
  - 素材是合成的，没有用真实 iPhone 或安卓视频验证。真实视频还可能带 HDR（10-bit）、杜比视界、实况照片（Live Photo）等，目前只处理了 8-bit 的常见情况。
  - 旋转符号约定（`rotation` 取负）靠合成素材 + 画面对比验证过，但只测了 90°（解析为 270°）。180° 与 0° 在单元测试里覆盖，没有端到端画面验证。
  - 标准化把音轨压成 16kHz 单声道 AAC，对 ASR 够用，但原始立体声音质丢失。需要保留原音质时要另存。
  - `data/normalized/` 里的产物不会自动清理，目录会随上传量增长。
- 下一步（调准）：B1 开始时对 `dog2.mp4` 之外的真实手机视频补一次验证。
