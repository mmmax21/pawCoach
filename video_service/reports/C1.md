# C1 置信度门控（unclear 片段 + 低 conf 轮次不进 summary）+ 跑通 + 记基线

- 预计工时：2h
- 验收命令：
  ```bash
  PYTHONPATH=. .venv-b/bin/python -m pawcoach.cli analyze data/raw/dog3.mp4 -o results/dog3.json
  # 期望：狗出画片段标 unclear，不进 summary；coach 说明「本段有 X 秒无法可靠判断」
  ```
- 验收结果：**通过**

## 做了什么

门控的「标记」这一半 B2/B3 早就做了（狗出画帧被 `in_frame_mask` 强制标 `unclear`），
C1 补的是「聚合 + 排除 + 报告」这一半：

1. `schema.py`：
   - `Quality` 加 `unclear_seconds`（unclear 片段总时长）、`unclear_ratio`（除以视频时长）。
   - `Summary` 加 `reliable_trials` / `unreliable_trials`（门控分组）。`success_rate` / `median_hold` 只基于可靠轮次。
2. `align.py` 加两个纯函数（门控聚合层，与对齐解耦）：
   - `unclear_seconds(pose)`：汇总 `label=="unclear"` 的片段时长。
   - `gate_trials(trials, conf_gate=CONF_GATE)`：按 `conf` 阈值把 trial 分成可靠 / 不可靠两组。
   - `CONF_GATE = 0.4`。
3. `cli.py`：
   - `summary` 的 `success_rate` / `median_hold` 只统计可靠轮次（`gate_trials` 的可靠组）；`unreliable_trials` 只计数、不进指标。
   - `dog_visible_ratio` 从硬编码 `1.0` 改成真值：读 `dogbox.npy` 缓存算「狗完整在画面」的帧占比（只读缓存，缺失回退 `1.0`，不隐式跑 YOLO）。
   - `unclear_seconds` / `unclear_ratio` 从 pose 算真。
4. `coach/template.py`：`unclear_seconds > 0` 时输出「本段有 X 秒无法可靠判断，未计入上述指标」；可靠轮次 < 总轮次时输出「其中 M 轮可靠，N 轮置信度不足」。

## 验收证据

- 单测 `tests/test_align.py` 新增 3 个用例（unclear 段不进 trial + 时长汇总、gate_trials 分组、边界 0.4/空列表），全量 **48 passed**（原 45 + 3）。
- dog3 端到端（`.venv-b` 真姿态 + 真口令）：

  | 字段 | 之前 | C1 之后 |
  |---|---|---|
  | `quality.dog_visible_ratio` | 硬编码 1.0 | **0.827**（17.3% 帧狗不在画面/不完整） |
  | `quality.unclear_seconds` | 无 | **19.334**（unclear_ratio 0.349） |
  | `summary.reliable_trials` | 无 | **4**（dog3 四轮 conf 0.475~0.55 全过阈值） |
  | `summary.unreliable_trials` | 无 | **0** |

  coach 输出末尾新增一句：`本段有 19.3 秒无法可靠判断，未计入上述指标。`

- 「出画 → unclear」链路实测（读 dogbox 算 in_frame mask，与真实 pose 的 unclear 段并排比对）：

  | 狗出画区间 | unclear 段 |
  |---|---|
  | 8.4–10.3s | 7.467–10.5s ✓ |
  | 34.6–37.2s | 33.833–37.867s ✓ |
  | 50.5–55.5s | 50.467–55.467s ✓ |

  三个出画区间全部被 unclear 段覆盖（其余 unclear 段来自低置信 / 正面视角，同样被门控）。

## 说明与遗留

1. **没有单独构造「狗出画」视频**，用 dog3 天然含 17.3% 出画帧验证了链路。计划原文写「构造一段出画视频」，但 dog3 本身就是含出画片段的真实视频，等效且更真实。
2. `CONF_GATE = 0.4` 只照 dog3 一只狗实测（trial conf 0.48~0.55、pose_conf_mean 0.46）取，**未做通用验证**，换狗/换角度可能要调。
3. unclear 段不区分原因（出画 / 低置信 / 正面视角混在一起），`dog_visible_ratio` 与 `unclear_ratio` 语义有重叠。真要分开得给 `PoseSegment` 加 `reason` 字段，C 阶段后续再说。
4. 「狗在 sit 过程中出画 → hold 被切短/算错」的切分问题仍是遗留（B8 已记），正确切分与跨轮奖励归因同属 C 阶段迭代项，C1 不修。
