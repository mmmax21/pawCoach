# C4 安全层（红旗 → 转介，不生成训练计划）+ 跑通 + 记基线

- 预计工时：1.5h
- 验收命令：
  ```bash
  # 给 meta.json 加 "red_flags": ["hitting"] 后
  PYTHONPATH=. .venv/bin/python -m pawcoach.cli analyze data/raw/sample.mp4
  # 期望：输出转介文本而非训练计划
  ```
- 验收结果：**通过**

## 做了什么

1. `pawcoach/coach/safety.py`（硬规则，优先于一切输出）：
   - 红旗定义分两类——狗的信号（`growling` 咆哮 / `baring_teeth` 龇牙 / `lunging` 扑咬 / `fear` 夹尾缩身躲避）+ 人的不当行为（`hitting` 打 / `kicking` 踢 / `jerking` 猛拉）。
   - `triggered_flags(meta)`：过滤出有效红旗（去重、保序、忽略未知）。
   - `referral_text(flags)`：生成转介建议文本。
2. `schema.py`：`MetaInfo` / `MetaModel` 加 `red_flags`（用户勾选的安全信号）。
3. `cli.py`：coach 之前拦截——有红旗直接 `referral_text`，不调 LLMCoach（**安全层优先于一切输出**）。

## 验收证据

- 单测 **77 passed**（原 73 + 新增 4：`test_safety.py`）。
- 端到端：给 `sample.meta.json` 加 `"red_flags": ["hitting"]` 后跑 analyze，输出：

  ```
  ⚠️ 本次视频检测到需要关注的信号，暂不生成训练建议。
  检测到：打狗。

  出于安全，请先停止当前的训练方式，并转介专业人士：
  - 狗狗有恐惧或攻击表现时，先看兽医排除疼痛或健康问题，再找认证的正向强化训犬师评估；
  - 不要用打、踢、猛拉等方式纠正——惩罚会加剧狗的恐惧和攻击（已有研究证实）。

  PawCoach 只适合记录和改善正向训练，不适合处理攻击或严重恐惧的情况。
  ```

  是转介文本，不是训练计划。验证后已恢复原 meta。

## 设计决策与遗留

1. **只做了「用户勾选」，没做「大模型对逐帧/音频描述的识别」**。原文是「用户勾选 + 大模型识别」两个来源，MVP 先只做前者——不训情绪模型、不引入额外推理。大模型识别（让 LLM 看逐帧描述/音频转写判红旗）是后续迭代项。
2. 转介文本是硬编码的通用版，没有针对单个 flag 的差异化措辞（比如「打狗」和「狗恐惧」的转介建议其实可以不同）。够用，后续可细化。
3. 红旗是用户自报的，不是系统自动检测的——这意味着「有攻击行为但用户不勾」时不会触发。这是 MVP 的已知局限，不是 bug。
