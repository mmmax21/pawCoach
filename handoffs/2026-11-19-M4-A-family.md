## 如何运行

**服务端**（默认端口 8000；先确认端口空闲 `lsof -iTCP:8000 -sTCP:LISTEN`，被占就换端口并同步改客户端地址）

```bash
cd server
.venv/bin/pip install -r requirements.txt     # 无新增依赖
DB_PATH=data/app.db FAKE_UPSTREAM=1 .venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

`DB_PATH` 默认 `server/data/app.db`。本次所有自测都用临时库和独立端口（8765 / 8766），未占用 8000。

```bash
cd app
flutter run -d emulator-5554
flutter run -d emulator-5556      # 第二台；用别的端口时加 --dart-define=SYNC_BASE_URL=http://10.0.2.2:<端口>
```

## 确定性主键派生方式

| 记录 | 主键 |
|---|---|
| WeeklyPlan.id | `plan_{dog_id}_{week_start}`（week_start 为 yyyy-MM-dd 周一）——`weeklyPlanId()` |
| PlanGoal | `(plan_id, skill_id)`（表结构本来就是复合主键） |
| DailyMiniTask | `plan_id` |
| WeeklyReport.id | `rep_{plan_id}`——`weeklyReportId()` |
| DogBadge | `(dog_id, badge_id)` |
| CareReminder.id | 默认条目 `care_{dog_id}_{template_id}_{seq}`，seq 为同一模板第几次（一次性项为 0）——`careReminderId()`；手动新增为 `care_u_<时间戳>` |

dog_id / household_id 由建档设备生成一次，之后随同步共享，所以上表在任何设备上都一致。同步记录里的复合主键用 `|` 连接，顺序同表定义（`sync_tables.dart` 与 `store.py` 的 `PK_SEP` 一致）。M3 已存在的随机主键计划保留原 id，不改写。

## schema 4 迁移内容（`AppDatabase.migrateToV4`）

1. 14 张已有同步表加 `client_updated_at TEXT DEFAULT ''` 与 `deleted BOOL DEFAULT 0`，并用各表时间列补 `client_updated_at`（统一成 UTC 毫秒 `Z`）：users / households / dog_concerns / weekly_plans / weekly_reports / ai_messages / diagnosis_results 取 `created_at`，household_members 取 `joined_at`，dogs / dog_cues / ai_conversations 取 `updated_at`，training_sessions 取 `ended_at`，plan_goals / daily_mini_tasks 无时间列，取迁移时刻
2. `dogs.initial_mastered`（JSON 数组）：用现有已掌握状态减去周报判定掌握的技能回填
3. `diagnosis_results.user_id`（可空，FM-5 诊断人；旧记录为空）
4. 新表：`care_reminders`、`dog_badges`（同步）；`local_accounts`、`sync_states`、`sync_outbox`、`sync_flags`、`badge_popups_seen`（不同步）
5. 每次打开数据库（新装与升级共用）：建 48 个触发器（每张同步表插入 / 更新 / 删除各一个），本地写入时自动写 `client_updated_at` 并进发件箱；应用下行数据与本地重算派生字段时置 `sync_flags.applying = 1`，不进发件箱

迁移测试 `test/m4_migration_test.dart`：用 M3 形态的库文件（建档、2 条记录、诊断、周报）退回 schema 3 后重开，行数全部一致、每条记录都有 `client_updated_at`、`initial_mastered` 回填正确、迁移后本地写入进入发件箱。

## 同步实现要点（供 Astra 理解）

- 匿名账号：首次需要同步时 `POST /v1/users`，然后把建档时的 `local_user` 换成服务端 user_id（users、household_members、households.creator_user_id、training_sessions.user_id、dog_badges.earned_by_user_id）
- 建家：本地有家庭但没有 `sync_states` 时，整体上传全部同步表（`POST /v1/households`），之后只推发件箱
- 节奏：同步表本地写入后约 150 ms 推送；前台每 5 秒 `tick`（补上传 → 推 → 拉）；回到前台立即 `tick`；切后台停止计时器
- 下行后：重算 Streak、DogSkillStatus（建档已会 + 周报判定 + 训练记录）、本周目标完成次数（不进发件箱），再判定徽章，并通知首页刷新
- 徽章判定时机：监听 training_sessions、diagnosis_results、weekly_reports、household_members、dog_skill_statuses 的写入，外加每次下行后
- 祝贺弹窗在跟练页、记录页上不弹，回到其他页面再弹；只有点"好的"才记为已弹

## 已知问题

- 匿名账号的 token 只存在本机：卸载重装等于新账号，旧设备上的家庭身份无法找回（简报 5.1 已接受）。
