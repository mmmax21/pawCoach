**转写方式为什么改成分句**：用合成口令实测，Whisper 整段转写（原 b5 方式）10 个口令只识别出 6 个（孤立的单字"坐""好"常被漏掉），时间戳还普遍提前约 1 秒。加 `initial_prompt` 会让它幻听出几十个"好"。换成分句转写后两段测试视频都是 10/10，起点误差在 0.06 秒以内，转写耗时约 3.8 秒。真实视频里有环境噪声，VAD 阈值按每段音频的底噪自适应，但效果还没验证过。整段模式保留着（`mode="whole"`），两种方式可以对比。

## 如何运行

### 1. 预热（演示前跑一次，需联网；之后现场不再下载）
```bash
cd video_service
conda activate pawcoach
python scripts/warmup.py
```
本机实测：5/5 OK，首次 77 秒（含下载 Whisper base 139MB 与 SuperAnimal 权重）。

### 2. 启动 video_service
```bash
cd video_service
./run.sh
```
- 默认 `0.0.0.0:8001`、`COACH_MODE=off`。`PORT=8002 ./run.sh` 可以换端口。
- 自查：`curl localhost:8001/` 应返回 `{"status":"ok","asr":"loaded|ready","pose":"ready","coach_mode":"off"}`。
- 8001 原先被 Docker 容器 `pawcoach-pawcoach-1`（队友旧版 compose，127.0.0.1:8001）占用。2026-11-18 经用户同意已执行 `docker stop`。该容器的重启策略是 `unless-stopped`，手动停止后 Docker 重启也不会再自动拉起。停掉后已确认 `./run.sh` 能在 `*:8001` 正常启动，健康检查正常。如果有人重新 `docker compose up`，`run.sh` 会报"端口已被占用"并打印占用进程。本次端到端用的是 8002。

2. `m4_astra_legacy_migration_test.dart` 每次运行都会改写 `tests/regression/m4a-2026-11-17/m3-upgrade.sqlite` 和 `migration-result.json`（这是测试本身的既有行为；本次会话开始前这个 sqlite 就已经是修改状态）。本次跑完测试后已用 `git checkout` 恢复这两个文件，`tests/` 下没有留下改动。
3. 分句转写依赖"口令之间有停顿"。主人连续说一长串话时，会整句交给 Whisper，句内的词级时间戳精度会下降。真实环境的噪声、狗叫声对 VAD 的影响还没验证过。
4. 服务端的奖励配对是"坐下后最近的一个奖励"，没给奖励的一轮会借到下一轮的奖励。App 端把落在下一轮开始之后的奖励视为不属于本轮（`_ownRewards`），避免误判"起身后才奖励"，但服务端返回的原始 `reward_t` 没有改。
5. 等待类技能的 `hold` 从坐下算起，而不是从说"等"算起，会比主人感知的等待时间略长（只会让"目标时长太长"更难触发，偏向漏报）。
6. 合成视频里的狗是静帧，姿态置信度（0.45 左右）可能和真实视频差别很大；`CONF_GATE=0.4` 是队友按 dog3 定的。
7. 模拟器相册里留着 3 段测试视频（`/sdcard/Movies/`）；模拟器上新装了包 `com.puppytrainer.puppy_trainer`（debug），和 Astra 的 `…astra` 包并存。
