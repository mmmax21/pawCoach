**转写方式为什么改成分句**：用合成口令实测，Whisper 整段转写（原 b5 方式）10 个口令只识别出 6 个（孤立的单字"坐""好"常被漏掉），时间戳还普遍提前约 1 秒。加 `initial_prompt` 会让它幻听出几十个"好"。换成分句转写后两段测试视频都是 10/10，起点误差在 0.06 秒以内，转写耗时约 3.8 秒。真实视频里有环境噪声，VAD 阈值按每段音频的底噪自适应，但效果还没验证过。整段模式保留着（`mode="whole"`），两种方式可以对比。

**后来又改成合并（hybrid，现在的默认）**：中文实拍上反过来，分句把两次"坐"都听成"走"，整段两次都认出（见"真实视频测试"第二段）。两种方式各有漏识，所以两种都跑、在事件层取并集（`asr.py` 的 `merge_events`）：以分句结果为主（时刻更准）；整段里的事件，若分句结果在 1.5 秒内有同类同词、还没配过的事件，算同一次，否则作为漏识补进来；一对一配对，所以相隔 1.4 秒的"坐、坐"不会合成一次。另有长词优先：一份转出"好了"、另一份在 1 秒内只转出"好"时，不多算标记词。没有 `alt_segments` 的旧缓存行为不变。

## 如何运行

### 1. 预热（演示前跑一次，需联网；之后现场不再下载）
```bash
cd video_service
conda activate pawcoach
python scripts/warmup.py
```
本机实测：5/5 OK，首次 77 秒（含下载 Whisper base 139MB 与 SuperAnimal 权重）。

### 2. 启动 video_service
```bash
cd video_service
./run.sh
```
- 默认 `0.0.0.0:8001`、`COACH_MODE=off`。`PORT=8002 ./run.sh` 可以换端口。
- 自查：`curl localhost:8001/` 应返回 `{"status":"ok","asr":"loaded|ready","pose":"ready","coach_mode":"off"}`。
- 8001 原先被 Docker 容器 `pawcoach-pawcoach-1`（队友旧版 compose，127.0.0.1:8001）占用。2026-11-18 经用户同意已执行 `docker stop`。该容器的重启策略是 `unless-stopped`，手动停止后 Docker 重启也不会再自动拉起。停掉后已确认 `./run.sh` 能在 `*:8001` 正常启动，健康检查正常。如果有人重新 `docker compose up`，`run.sh` 会报"端口已被占用"并打印占用进程。本次端到端用的是 8002。

### 真实视频测试（2026-11-18 补充）
用户提供的 `宠物狗训练模拟1.mp4`，就是队友报告里的 dog3，公开英文教程《Paragon Pups Sit Part 4》：55.5 秒，侧面拍摄，主人说英文 "sit" / "yes"。视频本身没有放进仓库，只放了服务端结果 `clips/real1_*.result.json` 和截图 `shots/12_real_video_app.png`。

| 项 | 结果 |
|---|---|
| 姿态 | **正常**。识别出坐姿段 1.9–7.5、11.9–19.2、27.4–34.3、39.1–50.3 秒，与画面里的 4 次坐下一致。`unclear_ratio` 0.37，未超过重拍门槛 0.5。 |
| 口令识别（英文词表） | **差**。主人每次说 "Sit"，Whisper（base 和 small 都试了）基本都听成 "That's"，只有 1 次听成能匹配上的 "Set"。只有开场解说里的 "ask for a sit" 配成了 1 轮。整段转写认出 4 次 "yes"，分句转写只认出 1 次：分句转写在合成口令上更准，在自然说话里反而漏得多。 |
| 按 App 实际方式（中文词表、`language=zh`） | 英文语音被强行按中文转写，出来是乱码，还从"做些什么"里误认出一个"坐"，配出 1 轮伪轮次。可靠轮次 1 < 2，**App 显示重拍提示**（截图 12）。 |
| 模拟器 → `10.0.2.2:8001` | 通 |
| 分析后删除 | 两次分析后 `data/` 下都没有残留 |

结论：
- 视频这一路（找狗、判坐站）在真实素材上可用。
- 口令识别是瓶颈：Whisper 不是专门做关键词识别的，听孤立短口令不可靠，真实环境下对中文口令的效果仍然未知。
- 英文视频不在 App 当前设计范围内：口令取自狗的中文口令表，语言固定为 `zh`。
- 重拍提示句写的是"看不清狗的姿势"，但这次的真实原因是口令没识别出来，提示会误导用户（对应"需要 Fable 决策"第 6 条）。

| 姿态 | **整段判为看不清**（`unclear_ratio` 1.0）。俯拍、正面视角下狗左右关键点间距过宽，`pose/rules.py` 的 `max_width_ratio` 按设计把画面当作正面视角，输出 unclear，0 轮。App 会显示重拍提示，这次提示的原因（看不清姿势）是对的。没有再走模拟器，因为判定是确定的：`unclear_ratio` 超过 0.5 就直接重拍。 |
| 口令"坐"（只用分句转写，原默认） | **两次都漏**：都被听成"走"。"好"认出 8 次。另外从"太好了"里切出一个"好了"，被当成释放词（误报）。 |
| 口令"坐"（整段转写） | **两次都认出**（1.0 秒、7.9 秒）。"好"认出 7 次，没有误报释放词。"握手"被听成"我闪"，"好乖"被听成"好哥哥"（本次不涉及这两个词）。 |
| 分析后删除 | `data/{uploads,normalized,pose,asr}` 为空 |

结论：
- 拍摄角度是第一道门槛：俯拍或正面拍会整段重拍，App 的拍摄说明（侧面拍到全身）必须让用户看到。
- 中文口令能识别，但两种转写方式各有漏识：合成视频上分句转写更好（10/10 对 6/10），这段实拍上整段转写更好（"坐" 2/2 对 0/2）。**已改为合并转写（hybrid）**，复测结果见下表。

**改为合并转写（hybrid）后复测**（同样的视频与词表，Whisper base）：

## 减少重拍（2026-11-18 补充）
用户反馈"需要重拍"体验差，按用户选定的三项实现：按原因提示、上传后快速预检、没听清口令时让用户补标。

### 1. 上传后快速预检（video_service）
- 新文件 `pawcoach/precheck.py`：从整段视频里均匀抽 16 帧（短视频每秒 1 帧，至少 6 帧），拼成短视频，只在这几帧上跑 YOLO + SuperAnimal。
  - 有完整狗的帧 < 30% → `no_dog`；
  - 有狗的帧里能判断姿势的 < 20% → `angle`（俯拍、正面）。
  - 只拦明显不行的视频（最终的重拍门槛是看不清 > 50%）。声音只记录（`voice`），不拦。
- `analyze_video(..., precheck=True, on_stage=…)`：只在 API 上传时开启。预检拦下时直接返回：`trials` 为空，`result.precheck.issues` 写明原因，不跑整段分析，同样删除视频。
- `GET /results/{id}` 在 pending 时带 `stage`（`precheck` / `analyzing`）。
- 实测：预检本身约 3 秒（首次约 13 秒，加载模型）。俯拍的中文实拍在服务端 **8 秒**返回 `angle`，在 App 里从选完视频到出提示约 **16 秒**；之前要等整段分析（约 1 分钟）。预检通过的视频总耗时多约 3 秒。

### 2. 没听清口令时补标（video_service + App）
- 结果新增 `events`：姿态段和识别到的事件，只有数字和命中的词。
- 新增 `POST /realign {result, meta, user_cue_sits}`：用户确认"这几次是听口令坐下的"后，用 `events` 重新对齐。视频已删除，不需要重传，同步返回。
- 补的口令放在坐下后 0.15 秒，走 align 已有的"口令落在进行中的坐姿里"分支：`latency=None`、`cue_times=[]`，`cue_source="user"`。用户只确认了喊过口令，没说什么时候喊的，所以反应快慢和口令重复都不算这几轮。奖励、结束方式、标记词照常计算。
- 再次补标以新的选择为准：`events` 里不存用户补的口令。
- App：重拍原因为"没听清口令"（或"没录到声音"）且有可补标的坐下时，重拍页列出"第 a–b 秒 狗坐下"，可以勾选，点"确认并重新判定"。重新判定后覆盖同一条历史记录（`VideoRepository.replace`），一次上传在历史里只占一行。失败时提示并保留勾选。历史页只读，不显示补标。

### 3. 按原因的重拍提示（App）
`RetakeReason` 从 2 种扩成 6 种，只取最主要的一个：

| 原因 | 触发 | 提示 |
|---|---|---|
| noDog | 预检 `no_dog` | 画面里大部分时间没有拍到完整的狗，请把狗全身放进画面后重拍 |
| wrongAngle | 预检 `angle` | 从这个角度看不出狗是坐着还是站着，请从侧面拍到狗全身后重拍 |
| tooUnclear | 看不清 > 50% | 原句不变 |
| noVoice | `audio_ok=false` / 无音轨 / 预检没听到说话声，且可靠轮次不足 | 这段视频没有录到说话声，听不到口令和奖励词，请打开声音、离手机近一些后重拍 |
| cueNotHeard | 可靠轮次不足，但"可靠轮次 + 没配上口令的坐下" ≥ 2，且结果带 `events` | 看到狗坐下了，但没听清口令。可以在下面标出哪几次是听口令坐下的，或者离手机近一些、清楚地说口令后重拍 |
| tooFewReliable | 其余 | 能确认的完整轮次不到 N 轮，请多练几轮后重拍（N 取内容库 `min_reliable_trials`） |
