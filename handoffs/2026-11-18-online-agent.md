# 交接：AI 教练在线模式——AI 助理训犬师（2026-11-18）

## 切题（比赛命题：给一个行业，造一位 AI 同事）

- **行业**：宠物训练服务。**岗位**：助理训犬师。
- **一句话**：一个训犬师只能带十几个学员、一周见一次；AI 助理训犬师每天跟进每一只狗，按专业规则安排训练、判断进度、调整计划，超出能力的情况转给兽医或专业训犬师。
- 与通用大模型的区别：它认识这只狗（档案、训练记录、本周计划），能动手（生成可确认的计划改动、开始跟练），守规则（只用内容库里的正向训练方法、健康问题必转兽医、计划改动走业务规则校验）。

| 命题要求 | 对应实现 |
|---|---|
| 行业理解 | 内容库：18 个技能（周龄窗口、前置、掌握标准）、9 类问题行为（诊断、方案、转介条件）、24 条常见问题，均标注公开来源 |
| 外部工具调用 | 8 个工具：狗档案、训练记录、本周计划、内容库检索、技能可练性检查、提议加入计划、开始跟练、转介 |
| 业务判断 | 计划改动复用 `addDiagnosisToWeek`（已掌握跳过、周龄、前置不满足时改练可练的前置、每周目标上限）；健康问题先拦截；拒绝惩罚性方法；连续两次没做到建议退回基础技能 |

## 两种模式

| | 离线（默认） | 在线 |
|---|---|---|
| 回答 | 内容库原文直出（原有实现，未改） | AI 助理训犬师：调用工具、结合狗的情况回答、标注出处 |
| 联网 | 否 | 是（`server/` 的 `/v1/agent`） |
| 健康问题 | 拦截，固定话术 | 同样先拦截，不调模型 |
| 写操作 | 无 | 只生成确认卡片；主人点确认时按同一规则重新校验后写入 |

切换：AI 教练首页和对话页右上角"离线 / 在线"，存在本机文件 `ai_mode.txt`（不进数据库、不同步）。构建参数 `AI_ONLINE=true` 可让默认值为在线。在线请求失败时自动改用离线回答并提示。

## 架构

```
App（Flutter）                                   server/（FastAPI）               模型
CoachAgent 循环（最多 6 轮）
  ├─ 健康拦截（checkHealthGuard）→ 命中则固定话术，结束
  ├─ POST /v1/agent {system, messages, tools} ─→ agent.py ──→ api_key：Claude 原生 tool use（claude-opus-5-5）
  │                                               │         cli：claude 命令行 + JSON 协议
  │                                               │         fake：固定剧本
  ├─ 收到 tool_use → AgentToolbox 在本机执行（读本机 SQLite；写操作只产生 AgentAction）
  └─ 收到最终回答 → 去掉 [ref: id] 记为出处 → 正文 + §trace 过程行 + §action 卡片行 一起入库
```

- 工具执行在 App 端：数据都在手机本机数据库里，服务端不接触狗档案和训练记录。
- 卡片与过程编码在消息正文末尾（`§trace …`、`§action …`），不改表结构、不影响同步；历史对话重新打开也能显示卡片。
- 模型的 thinking 等块原样带回下一轮（服务端返回全部块）。

## 如何运行

```bash
cd server
CLI_UPSTREAM=1 .venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000   # 没有 API key：用本机已登录的 claude 命令行
# 或：export ANTHROPIC_API_KEY=... 后不加 CLI_UPSTREAM
```

App 照常运行（模拟器默认连 `http://10.0.2.2:8000`），AI 教练页切到"在线"。

## 演示脚本（约 3 分钟）

1. AI 教练页展示"离线 / 在线"开关，说明离线 = 内容库原文、在线 = AI 助理训犬师。
2. 切到在线，在某个技能页点"问教练"，问："坐下老学不会，要不要凶它？"
3. 画面逐条出现"查看狗狗档案 → 查看训练记录 → 查看本周计划 → 检索训练内容库 → 按规则检查能不能练"。
4. 回答：拒绝凶它并给替代做法；按规则指出前置技能还没掌握，建议先练前置；下方出现"加入本周计划"确认卡片或"开始跟练"按钮。
5. 点确认 → 回首页，本周目标里出现该技能（说明计划真的改了，并且是经过规则校验的）。
6. 再问："它今天有点拉肚子还练吗？" → 立即回复建议就医，不调模型。
7. 可选对比：同一个问题问 ChatGPT，对比"不认识你的狗、不能动手"。

  - 一次提问约 1–2 分钟（命令行上游每轮要启动一次命令行进程）；用 API key 上游会快很多。
- **第三方中转 API key 上游**（2026-11-18，Anthropic 格式接口，`ANTHROPIC_BASE_URL` + `ANTHROPIC_API_KEY` + `FALLBACKS=off`）：
  - 原生工具调用可用：首轮 4.1 秒返回 3 个工具调用；第二轮带回工具结果后 `end_turn`，thinking 块原样往返正常；两轮合计约 7 秒。effort 参数被接受。
  - App 里在线提问，一次回答约半分钟到一分钟（含多轮工具调用）。
  - 发现并修复一个问题：模型只查了某个技能的训练记录、结果为空时，误以为整只狗没有记录，并"更正"了前一次正确的说法。修复：训练记录工具对错误的技能 ID 报错，按技能筛选为空时写明"只是该技能没有记录"并给出全部技能的记录数；系统提示增加"事实只来自工具结果、不把单个技能的结果推广到整只狗"。复测后回答与数据库一致。

## 已知问题与风险

1. **命令行上游较慢**：每轮约 8–20 秒，多轮工具调用一次提问要 1–2 分钟。演示建议用 API key 上游，或提前准备好问题。
2. **命令行上游不是原生工具调用**：靠提示词约束模型只回 JSON，模型偶尔不按格式时，服务端把整段当作最终回答（不丢内容，但这一轮不会执行工具）。
3. **出处依赖模型标注**：模型没写 `[ref: id]` 时，出处退回为"本次检索到的资料"。
4. 在线回答的正文由模型生成，不再是内容库逐字原文（这是在线模式的定义）；健康拦截、计划规则校验、确认后才写入这三条硬边界不依赖模型。
5. **第三方中转**：数据（狗档案、训练记录、对话）会经过中转站；中转站转售额度不一定符合 Anthropic 使用条款，模型是否为官方模型无法验证。只建议用于演示；key 只通过环境变量传入，不进代码、不提交。
6. 模拟器键盘：为了测试输入英文，把模拟器 Gboard 从拼音切到了 US 布局，需要时在键盘上切回。
