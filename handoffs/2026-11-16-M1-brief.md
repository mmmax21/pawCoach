## 1. M1 目标

一个能跑在 iOS 模拟器和 Android 模拟器上的 Flutter 应用，做到：

1. 启动时加载 `content/` 下的全部 YAML 到本地数据库。
2. 新用户完成三步建档。
3. 建档完成立即生成首周计划，并在首页展示。
4. 所有数据先写本地，服务端同步接口定义好但可以先用本地假实现。

M1 不做：跟练、打卡、周报、AI、推送、家庭邀请。这些是 M2-M4。

## 3. 技术约束

- **Flutter 3.x stable，Dart 3**。
- 状态管理用 **Riverpod**，本地库用 **drift**（sqlite）。路由用 **go_router**。不要引入其他状态管理或 ORM。
- 目录结构按功能分层：

```
app/lib/
├── main.dart
├── app.dart                     # MaterialApp + router
├── core/                        # 主题、常量、工具
├── data/
│   ├── db/                      # drift 表定义与 database.dart
│   ├── content/                 # YAML 加载与内容库仓库
│   ├── repositories/            # dog / household / plan 仓库
│   └── sync/                    # 同步接口定义 + 本地假实现
├── domain/                      # 纯 Dart 模型与规则（周计划生成器在这里）
└── features/
    ├── onboarding/
    ├── home/
    └── skill_tree/              # 本期只做数据层，UI 留 M4
```

- 内容库 YAML 打进 assets（`app/assets/content/`，构建时从仓库根 `content/` 复制，写一个脚本 `app/tool/sync_content.sh`）。不要手抄内容，不要把任何技能步骤写进 Dart 代码。
- 周计划生成器放在 `domain/plan_generator.dart`，**纯函数，无 IO**，输入狗档案 + 技能列表 + 问题行为列表，输出计划。这是本期单测重点。
- 所有时间存 UTC ISO 8601，周起始为周一。

## 4. 周计划生成规则（WP-2 细化，以此为准）

输入：狗的周龄 `age_weeks`、已掌握技能集合 `mastered`、困扰列表 `concerns`、每日时长 `daily_minutes`。

```
1. 候选 = 所有技能中满足以下全部条件的：
     min_age_weeks <= age_weeks
     id 不在 mastered
     prerequisites 全部在 mastered（无前置则直接满足）

2. 困扰技能集 = concerns 中每个 issue 的所有 solutions[*].skills 的并集

3. 排序键（升序）：
     (是否困扰技能 ? 0 : 1, difficulty, min_age_weeks, id)

4. 目标数 N 按 daily_minutes：5→2，10→3，15→3，30→4

5. 基础保障：若 marker_intro 或 name_response 不在 mastered 且在候选中，
   强制放入目标前两位（先 marker_intro 后 name_response），占用 N 的名额。

6. 取排序后前 N 个为本周目标。每个目标 target_sessions = 该技能 sessions_to_master + 1，
   source 按来源填：基础保障→"age"，困扰技能→"concern"，其余→"age"。

7. 保底任务 DailyMiniTask：
     若 mastered 非空，取 mastered 中 difficulty 最低者（并列取 id 字典序最小），script_part = 1；
     否则取本周目标中 difficulty 最低者，script_part = 1。

8. 候选为空（极端情况：全部掌握或周龄不够）：
     目标为空，保底任务取 mastered 中 difficulty 最低者；两者都空时首页显示"去狗档案调整信息"。
```

用内容库 v1.0 跑过的预期结果，作为单测用例：

| 输入 | 期望目标（有序） |
|---|---|
| 8 周，无掌握，困扰 biting_hands，10 分钟 | marker_intro, name_response, redirect_to_toy |
| 12 周，掌握 {name_response, lure_follow, marker_intro, sit}，困扰 potty_accidents，15 分钟 | crate_intro, potty_training, redirect_to_toy |
| 20 周，掌握 {name_response, lure_follow, marker_intro, sit, down, stay_short, leash_intro, recall_indoor}，困扰 leash_pulling，30 分钟 | calm_settle, loose_leash, redirect_to_toy, bite_inhibition |
| 8 周，无掌握，无困扰，5 分钟 | marker_intro, name_response |

（第 3 行 calm_settle 与 loose_leash 都是困扰技能且 difficulty 分别为 3、4；redirect_to_toy 是非困扰 difficulty 1；bite_inhibition 与 crate_intro 同为 difficulty 2、min_age_weeks 8，按 id 字典序 bite_inhibition 在前。）

## 5. 内容库加载

- 启动时读 `assets/content/skills/*.yaml`、`issues/*.yaml`、`badges.yaml`、`care_calendar.yaml`，解析后写入 drift 表 `content_skills`、`content_issues`、`content_badges`、`content_care_items`，整体存 JSON 列即可，不必拆成关系表。
- 记录 `content_version`（取 `VERSION.md` 第一个 `## v` 标题），版本相同则跳过重载。
- 解析失败要抛出带文件名的异常，不能静默吞掉。
- YAML 解析用 `yaml` 包。注意 `script_parts` 字段可能不存在（默认 1），`downgrade_to` 可能为 null，`default_gesture` 以"无"开头时不展示手势图。

## 6. 建档细节

**第一步 狗的基本信息**
- 名字（必填，≤10 字）
- 出生日期（日期选择器，默认 10 周前；派生周龄实时显示）
- 品种：搜索框 + 列表，本期内置 30 个常见品种硬编码在 `core/breeds.dart`（这是唯一允许硬编码的列表），末尾固定"混种 / 不确定"
- 性别（公 / 母）
- 入户日期（默认今天）

**第二步 当前困扰**
- 从 9 个 issue 中多选，最多 3 项，可跳过
- 每项显示 `name` 和 `typical_age_weeks` 转成"常见于 X-Y 月"

**第三步 主人条件**
- 每天可投入：5 / 10 / 15 / 30 分钟（单选）
- 家里几个人会训：1 / 2 / 3+（单选）
- 居住环境：公寓 / 带院子（单选）
- 已经会的技能：按 `min_age_weeks` 排序的 18 个技能复选，默认全不选

**完成**
- 写入 Household、HouseholdMember（creator）、Dog、DogConcern、DogSkillStatus（勾选的为 mastered，其余按前置是否满足设 available / locked）、DogCue（全部技能的默认口令）
- 调用计划生成器，写入 WeeklyPlan、PlanGoal、DailyMiniTask
- 跳转到计划预览页，再进首页

## 7. 首页（WP-3 静态版）

- 顶部：狗名 + 周龄 + 连续打卡天数（本期恒 0）
- 本周目标列表：技能名、难度星、`0 / target_sessions`
- 今日保底任务卡片：技能名 + "约 N 分钟"（N = 该 script part 的 duration_sec 之和向上取整到分钟）
- 点击任一项进入技能详情页：显示 `tutorial.summary`、`steps`、`common_mistakes`、`success_criteria`。跟练按钮本期置灰。

## 8. 同步接口（只定义）

`data/sync/sync_service.dart` 定义接口：

```dart
abstract class SyncService {
  Future<void> pushPending();

```
