## 1. M2 目标

在 M1 基础上，做到：

1. 从首页进入任一技能，能看教程、能全屏跟练，跟练时计时和语音在锁屏、切后台后继续。
2. 跟练结束自动进入记录页，打卡 + 三档评分 + 备注写入本地库。
3. 首页显示真实的完成次数、连续打卡天数和本周进度条。
4. 每周日晚自动生成周报，并按 WP-6 规则产出下周计划；用户打开 App 时能看到。
5. M1 遗留：ON-7 狗档案页、保底任务改取 `mini_script`。

M2 不做：AI 教练、推送通知、家庭邀请、徽章、视频备注上传（本地只存路径）。

## 5. 跟练状态机（TR-2 / TR-3 / TR-6）

一次跟练 = 一个技能的一个 `script_part`。状态机放 `features/training/training_controller.dart`，纯 Dart 逻辑与 UI 分离，便于单测。

```
idle → running(step i) → paused → running
                       → stepDone → running(step i+1)
                       → skipped(i) → running(step i+1)
                       → restarted(i) → running(step i)
       running(last) → stepDone → finished → 跳记录页
```

- 进入 step i：若 `voice: true`，TTS 朗读 `instruction`；倒计时从 `duration_sec` 开始。
- 倒计时归零：TTS 说"下一步"，自动进入 i+1。用户也可手动点"下一步"提前进入。
- `clicker_hint: true` 的步骤：响片按钮高亮，上方显示"狗做对的瞬间按下"。响片按钮始终可按（不限步骤），点击播放响片音效并 `clicker_count++`。
- "重来一次"：倒计时重置为 `duration_sec`，重新朗读。
- "跳过"：记入 `skipped_steps`，直接进 i+1。
- 暂停：倒计时停，TTS 停。锁屏不等于暂停。
- 最后一步结束 → `finished`，`ended_at` 取此刻，自动 `context.go` 到记录页并带上 session 草稿。
- 用户中途退出（返回键）：弹确认，确认后丢弃本次，不写 TrainingSession，不算打卡。

## 6. 后台音频与锁屏（TR-4）

这是本期技术风险最高的一项，先做可行性验证再做 UI。

- Android：`audio_service` 前台服务，通知栏显示技能名 + 当前步骤 + 剩余秒数，带"暂停 / 下一步"按钮。
- iOS：`Info.plist` 加 `UIBackgroundModes: [audio]`；`audio_service` 保持会话活跃；锁屏控制中心显示技能名 + 当前步骤。
- 计时不靠 Dart `Timer` 在后台跑。记录每步的 `step_started_at` 绝对时间，回到前台或收到 audio_service 的 tick 时按差值重算剩余秒数。这样切后台 30 秒再回来，倒计时是准的。
- TTS 在后台要能发声：iOS 需要 audio session category `playback`；Android 走前台服务进程。
- 响片音效：`assets/audio/clicker.wav`，Fable 提供 CC0 素材；找不到就先用合成的短促方波占位，在交接单注明。
- 配图：`tutorial.steps[*].image` 和 `script` 都引用了 `xxx_stepN.png`，本期内容库没有图片文件。跟练页显示"图片占位 + 步骤序号"，不要因为文件缺失崩溃或白屏。图片本身排在 M4 与分享卡片一起由 Fable 出。
- 验收标准：锁屏 60 秒后解锁，倒计时误差 ≤2 秒，期间 TTS 至少正常朗读一次"下一步"。

## 7. 保底任务改取 `mini_script`（WP-1）

内容库 v1.1 每个技能新增字段：

```yaml
mini_script:                     # 每日保底版，总时长 ≤ 300 秒
  - step: 1
    instruction: ...
    duration_sec: 60
    voice: true
    clicker_hint: true
```

- `content_parser.dart` 加解析，`mini_script` 缺失视为解析错误（v1.1 起必填）。校验总时长 ≤300，超过抛异常。
- `DailyMiniTask` 表的 `script_part` 字段保留但含义改为：`0` 表示 `mini_script`，`≥1` 表示正式脚本的 part。M2 生成器一律写 `0`。
- 生成器第 7 条规则不变（取谁），只是跟练时读 `mini_script` 而不是 `script`。
- 首页"约 N 分钟"改按 `mini_script` 求和。
- 保底任务跟练完成也写 TrainingSession，`script_part = 0`。

## 8. ON-7 狗档案页与重新生成规则

- 页面：显示 M1 建档的全部字段，每项可改；口令表（DogCue）按技能列出，口令词和手势描述可改。
- 改出生日期、困扰、每日时长中任一项并保存后：
  - 若本周尚无任何 TrainingSession：直接用 M1 生成器重生成本周计划，覆盖 PlanGoal 与 DailyMiniTask。
  - 若本周已有记录：不动本周，标记 `weekly_plans.regenerate_next = true`，下周生成时走"全新生成"而不是 WP-6 调整。
- 改名字、品种、性别、入户日期、居住环境、训练人数：只更新 Dog，不触发计划变化。
- 改口令：只更新 DogCue。跟练页朗读 instruction 时**不替换**口令词（内容库文案里的口令是示例，替换会破坏句子），只在跟练页顶部常驻显示"你的口令：X"。

## 9. 周报与下周计划（WP-5 / WP-6）

**触发**：
- 每周日本地时间 21:00 由 `workmanager` 触发 `weekly_job`。
- 兜底：App 每次冷启动检查"当前活动计划的 `week_start` 是否已早于本周一"，是则立即补跑。两条路径调用同一个幂等函数，以 `plan_id` 去重，不会生成两份。

**周报汇总**（`domain/weekly_report.dart`，纯函数）：
- 输入：本周 WeeklyPlan + PlanGoal + 本周所有 TrainingSession + Streak。
- 每个目标：完成次数、三档评分计数、`outcome`。
- `checkin_days`：本周有 session 的不同本地日期数。
- `comment`：取本周评分最低的目标技能的 `scoring_hint`；没有记录时固定"这周还没开始，下周从保底任务做起"。

**下周计划规则**（`domain/plan_generator.dart` 新增 `nextWeekPlan()`，纯函数）：

```
对本周每个目标 goal：
  full  = 本周该技能 score == full 的次数
  none  = 本周该技能 score == none 的次数

  1. full >= 2         → outcome = mastered
                         DogSkillStatus 置 mastered，不进下周
  2. 否则 none >= 2    → outcome = downgrade
                         下周目标 = 该技能的 downgrade_to（source = downgrade）
                         downgrade_to 为 null 时，下周保留本技能（source = carryover）
  3. 否则              → outcome = carryover
                         下周保留本技能（source = carryover）

下周目标集合 = 上述 downgrade + carryover 的技能（去重），
  再调用 M1 的 generateWeeklyPlan() 按新周龄、新 mastered 补足到 N 个，
  补入的技能排在 carryover / downgrade 之后。
  若 carryover + downgrade 已 ≥ N，不补，也不裁，允许超过 N。

保底任务：按 M1 第 7 条规则用新 mastered 重算。

regenerate_next == true 时跳过上述全部，直接 generateWeeklyPlan()。
```

- 旧计划 `status` 改 `completed`，新计划 `status = active`，`generated_by = system`。
- 用户打开 App 若发现有新周报未读，首页顶部显示"上周周报已生成"入口，点进周报页。
- 周报页：评分汇总表、打卡天数、comment、"下周计划预览"（直接复用 M1 预览页组件）。

## 10. 打卡与连续天数（RC-2 / RC-3 / ST-1）

`domain/streak.dart` 纯函数：

```
输入：所有 TrainingSession 的 started_at（转本地日期去重）、今天本地日期
current_days：从今天（或昨天，若今天还没练）往前连续有记录的天数
longest_days：历史最长连续
last_checkin_date：最近一次
```

- 每写一条 TrainingSession 后重算并写 Streak 表。
- 首页连续天数来自 Streak，不要每次渲染都扫表。
- 本周进度条 = 本周所有目标 `completed_sessions` 之和 / `target_sessions` 之和，保底任务不计入。

## 11. 测试要求

- `training_controller` 状态机单测：正常走完、跳过、重来、暂停恢复、中途退出；后台 30 秒后倒计时重算。
- `nextWeekPlan()` 单测，用内容库 v1.1 跑：
  - sit 两次 full → 下周无 sit，DogSkillStatus mastered，down 进入候选
  - sit 两次 none → 下周出现 lure_follow（source downgrade）
  - crate_intro 两次 none（downgrade_to 为 null）→ 下周保留 crate_intro（source carryover）
  - 一次 full 一次 none → carryover
  - 本周零记录 → 全部 carryover
  - regenerate_next → 全新生成
- `streak` 单测：连续 3 天、中断、今天未练但昨天练了、跨月。
- `weekly_report` 单测：汇总计数正确，comment 取最低分技能。
- 周报幂等：同一 plan_id 跑两次只生成一份。
- `mini_script` 解析：缺失抛异常、超 300 秒抛异常。
- 集成测试（沿用 Astra 的 `integration_test/`）：跟练一次 → 记录页 → 首页完成次数 +1、连续天数 1。
