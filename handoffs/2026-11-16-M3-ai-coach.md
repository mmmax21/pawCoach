在设备上发现并修掉的问题（都已回归 287/287）：
1. 新消息入库后列表不自动滚动，固定话术（没有流式过程）会落在屏幕外 → 消息数变化时滚到底（懒加载列表要滚两次）。
2. 发送中把输入框设为禁用，会断掉输入法连接；回答结束后第二次输入打不进去 → 发送中只禁用发送按钮，输入框保持可用（`_send` 本来就会忽略发送中的重复调用）。
3. 气泡里的 ListTile（参考内容）没有 Material 祖先，点击效果画不出来并报断言 → 气泡底色改用 Material。
4. 构建：`flutter_local_notifications` 23 / `androidx.core` 1.19 要求 compileSdk ≥ 37 → `compileSdk = maxOf(flutter.compileSdkVersion, 37)`，targetSdk / minSdk 不变。

## 已知问题

1. **temperature 0 做不到**：`claude-sonnet-5-5` 对非默认 temperature 直接返回 400，代理不传 temperature。见"需要 Fable 决策"第 1 条。
2. **真实模型未验证**：见上。系统提示是否足以让模型只用资料、末尾带 `[ref]`、资料不足时回固定话术，都要靠 Astra 的真实回归判断。`[ref]` 缺失或 ID 越界时会打 `[ai] ref_missing` / `ref_invalid` 日志（`flutter logs` 可见），回答照常展示、`cited_content_ids` 为空。

### 等价性四点

| 要求 | 实现方式 | 是否实测 |
|---|---|---|
| 系统提示整体替换 | `--system-prompt=<客户端系统提示>`，用等号形式避免内容以 `-` 开头被当成参数，不用 `--append-system-prompt`。`--help` 写明 `--exclude-dynamic-system-prompt-sections` 在使用 `--system-prompt` 时被忽略，说明不会再插入默认动态段 | 参数在替身测试里断言过，真实命令行能接受这个参数。**模型实际看到的系统提示是否只有这一份，未实测**（需要登录） |
| 不加载指令 / 记忆 / 技能 / 钩子 / MCP，在空临时目录运行 | 每个请求 `mkdtemp` 一个空目录作为 cwd，用完删除；`--setting-sources ""`（不读 user / project / local 设置）；`--safe-mode`（关掉 CLAUDE.md、技能、已装插件、钩子、MCP、自定义命令与代理、输出风格）；`--strict-mcp-config` 且不给 `--mcp-config`；`--disable-slash-commands`；`--no-session-persistence`。另外运行时核对 `init` 事件，技能 / 斜杠命令 / MCP 任一非空就报错 | 部分实测：真实 `init` 里技能、斜杠命令、MCP 都为空，设置里的 key 没被读到。**残留风险**：①不能用 `--bare`（它的认证只认 API key、读不到订阅登录），所以 `init.plugins` 里仍有 5 个内置插件（`cc-plugin-*@builtin`），它们会不会往请求里加内容没有逐一核实；②自动记忆有没有注入，未实测 |
| 禁用全部工具 | `--tools ""`；运行时核对 `init.tools` 必须为空，否则 `CliToolsEnabled` | 已实测：真实 `init.tools=[]` |
| 模型固定、多轮历史原样 | `--model $MODEL`，不传 `--fallback-model`；运行时核对 `init.model == MODEL`，否则 `CliModelMismatch`。单轮：提示原文从 stdin 直传 | 模型：已实测，真实 `init.model=claude-sonnet-5-5`。多轮：**做不到完全等价**，见下 |

**多轮历史不等价**：`--help` 里没有注入以往 assistant 回合的参数。我实测了 `--input-format stream-json`：每条 user 行都会触发一次新的回答，assistant 行没有文档说明会作为历史。所以多轮时把历史按原顺序、每条带原角色写成 `<turn role="user|assistant">…</turn>`，放进最后一条用户消息。每条单独成段，不合并不丢弃，但模型看到的结构不是真正的多轮。影响：课程内提问按 (狗, 技能) 复用对话，同一技能连续问时第二问起会带历史。建议 Astra 跑 30 + 10 题时，每题用新对话（例如每题前清掉该技能的对话，或用不同技能 / 自由提问）保证单轮，这样结果和真实接口等价。

## Fable 复核：打卡抑制根因与缺口裁定（2026-11-17）

### 新缺陷 BUG-M3-002（中，ST-7 不符 PRD）

**现象**：打卡后界面显示下次提醒为明天 19:00，系统闹钟却排在今天 19:00（Astra 第二轮补充"打卡后当天抑制"一行）。

**根因（Fable 读代码确认）**：`app/lib/services/reminder_service.dart` 的 `scheduleDaily` 调用 `zonedSchedule` 时带了 `matchDateTimeComponents: DateTimeComponents.time`。`flutter_local_notifications` 23.0.2 的 Android 实现在这种情况下会**丢弃传入的日期**，按"现在之后最近的同一时刻"重算首次触发时间（`FlutterLocalNotificationsPlugin.java` 中 `zonedSchedule` 调用 `getNextFireDateMatchingDateTimeComponents`）。所以只要打卡发生在提醒时刻之前，`nextReminderAt` 算出的"明天"在系统层面变回"今天"，当天照常弹出。单测用的是假通知后端，覆盖不到插件这层，因此 287/452 全绿也没发现。

**修复方向（Fable 决定，由 Astra 实现）**：
- 不再用 `matchDateTimeComponents` 做每日重复。改为一次性排定未来 **14 天**的单次通知，每天一个独立 ID（如 1001–1014），已打卡的当天不排。
- 在三个时机整体重排（先全部取消再排）：App 启动、打卡后、提醒设置变更。
- 14 天内一次都不打开 App 时提醒会停，接受；这与 M4 的 AI-5"连续 3 天无打卡推送"另行处理，不在本缺陷范围。
- 重启后恢复依赖插件对单次通知的开机重排，需设备复核。
- 补单测：重排后的 ID 集合与日期集合（打卡前、打卡后、提醒时刻已过三种情形）。补设备测：打卡后把提醒设到几分钟后，越过该时刻确认**不弹**，并在系统闹钟列表里确认最早一条是明天。
