## 1. M3 目标

1. AI 教练能回答课程内提问，回答只来自内容库，附参考条目。
2. 问题行为诊断：按内容库诊断树追问，输出方案，可一键加入计划。
3. 内容库外问题和健康类问题 100% 返回固定话术。
4. 每日提醒推送，已打卡则不推。
5. AI 边界测试题集 90 题全部通过，作为验收的硬门槛。

M3 不做：视频分析（AI-4，P2）、主动干预（AI-5，排 M4）、家庭共享、徽章、疫苗日历。

## 3. 技术约束

- 模型：`claude-sonnet-5-5`，temperature 0。

## 5. AI 回答边界（AI-1，硬性）

处理顺序固定为三层，前一层命中就不进下一层：

**第一层 健康拦截（`ai_guard.dart`）**
- 用户消息命中健康词表任一项 → 不调模型，返回固定话术，`kind = guard_health`。
- 健康词表放 `assets/content/ai_guard.yaml`（Fable 已提供，见第 11 节），不写在 Dart 里。词表分三组：`hard`（命中即拦）、`soft`（命中且同句无 `training_terms` 中任一词时拦）、`training_terms`（训练语境词）。全部为子串匹配。
- 固定话术：`涉及狗狗健康的问题，请尽快咨询兽医。训练上的问题我随时在。`

**第二层 检索（`retrieval.dart`）**
- 内容库只有 27 条，不做向量库。检索分两步：
  1. 上下文直取：课程内提问带 `skill_id`，该技能的 `tutorial`、`common_mistakes`、`success_criteria`、`scoring_hint` 必入；诊断对话带 `issue_id`，该 issue 全文必入。
  2. 关键词打分：对用户消息做中文分词（用 `assets/content/ai_terms.yaml` 里的词表做最大匹配，Fable 提供），对每个技能和问题行为算命中词数，取前 3 个追加。词表里每个词可映射到若干内容 ID，比如"坐" → sit，"咬" → biting_hands、bite_inhibition。
- 无命中判定：上下文直取为空，且关键词打分最高分为 0 → `kind = guard_no_hit`，不调模型。
- 固定话术：`这个问题内容库暂时没有覆盖，建议咨询专业训犬师。`

**第三层 模型生成（`prompt_builder.dart` + 服务端）**
- 系统提示结构：
  1. 角色：幼犬训练助手，只能依据给定资料回答。
  2. 硬规则：资料里没有的方法不说；不给医疗建议；不编造数据；回答末尾用 `[ref: id1, id2]` 标出用到的资料 ID；如果资料不足以回答，只回复"这个问题内容库暂时没有覆盖，建议咨询专业训犬师"。
  3. 狗档案摘要：名字、周龄、困扰列表、已掌握技能、该技能最近 3 次评分（AI-2 要求）。
  4. 资料块：检索结果，每条带 ID 和原文。
- 客户端解析回答末尾的 `[ref: ...]`，存入 `cited_content_ids`，正文去掉这段后展示。`[ref]` 缺失或 ID 不在检索集合内时，仍展示回答，但 `cited_content_ids` 为空并打日志（Astra 回归关注）。
- 回答中若出现固定话术原文，`kind` 改为 `guard_no_hit`。

## 6. 课程内提问（AI-2 / AI-6 / AI-7）

- 入口：技能详情页和跟练页右上角"问教练"。跟练页进入时先暂停跟练（复用 M2 状态机的暂停），返回后恢复。
- 带上下文：`skill_id`、当前 `step`（跟练页）、该技能最近 3 次 `TrainingSession.score`。
- 对话页：流式显示；每条助手消息下方"参考内容"折叠区，展开列出 `cited_content_ids` 对应的技能名或问题名，点击跳技能详情页。
- 对话按 `(dog_id, skill_id)` 复用同一个 `AiConversation`，不每次新建。
- 历史消息发给模型时只带最近 10 条。

## 7. 问题行为诊断（AI-3 / WP-8）

- 入口：底部 Tab "AI 教练" → "问题诊断"。
- 流程：
  1. 列出 9 个问题行为供选择（也可输入描述，走第 5 节检索取最高分 issue，没有则 `guard_no_hit`）。
  2. 按该 issue 的 `diagnosis_tree` 逐题追问，每题的选项直接渲染为按钮，**不调模型**。遍历逻辑在 `diagnosis.dart`：输入 issue 和已选路径，输出下一题或 result。
  3. 到达 result 后，渲染 `solutions[result]`：`summary`、`skills`（显示技能名和当前掌握状态）、`management`、`escalate_if`。这一步也不调模型，全部是内容库原文。
  4. 底部两个按钮："加入本周计划""加入下周计划"。
  5. 结果页之后可以继续自由提问，这时走第 5 节三层流程，上下文带 `issue_id`。
- 加入计划规则：
  - 本周：对 `solution.skills` 中每个技能，若前置已满足且不在本周目标中，追加为 `PlanGoal`，`source = ai_diagnosis`，`target_sessions = sessions_to_master + 1`；前置未满足的跳过并提示。本周目标上限放宽到 6。
  - 下周：写 `DiagnosisResult.added_to_plan_id = null` 并在 `WeeklyPlan` 上标记 `pending_diagnosis_skills`（新列，JSON 数组），`nextWeekPlan()` 生成时优先放入（排序键最前，`source = ai_diagnosis`）。
  - `escalate_if` 的处理：结果页必须完整展示 `escalate_if` 原文，放在方案前面，用醒目样式。诊断本身不做"是否已触发升级"的判断，那是主人自己对照的。

## 8. 提醒推送（ST-7）

- 设置页：开关 + 时间选择，默认关闭，默认时间 19:00。
- 用 `flutter_local_notifications` 按本地时区每天调度。
- 触发时检查：若今天该狗已有 `TrainingSession`（按 M2 的归日规则），不显示通知。实现方式：通知内容在调度时就写死为"今天还没练，去看看本周目标"，但在 App 每次打卡成功后取消今天的待发通知并重新调度明天的。这样不依赖后台执行代码。
- 点通知打开首页。
- Android 13+ 要申请通知权限，首次打开开关时请求。

## 9. 服务端代理

`server/main.py`：

```
POST /v1/chat
body: { system: string, messages: [{role, content}], max_tokens?: int }
response: text/event-stream，每个事件 data 为增量文本，结束事件 data: [DONE]
```

- 环境变量 `ANTHROPIC_API_KEY`、`MODEL`（默认 claude-sonnet-5-5）、`PORT`。
- 不做鉴权（首版本地跑），README 里写清这是临时方案。
- 客户端 `ai_client.dart` 的 base URL 从 `--dart-define=AI_BASE_URL=` 读，默认 `http://10.0.2.2:8000`（Android 模拟器访问宿主机）。
- 网络失败：对话页显示"教练暂时联系不上，稍后再试"，消息不入库。

### 16.1 模式开关

- 构建参数 `--dart-define=AI_MODE=library|model`，**默认 `library`**。
- `library`：全程本地，不发任何网络请求，离线可用。对话页不出现"正在思考"和"教练暂时联系不上"。
- `model`：保持现有实现原样（`ai_client`、`prompt_builder`、`server/`），不删代码，现有相关测试继续通过。本期不再对它做真实模型验证。

### 16.2 直出组装器

新增 `app/lib/domain/answer_composer.dart`，纯函数，无 IO、无 Flutter。输入：检索结果（含上下文条目与关键词命中条目及得分）、提问上下文（`skill_id`、当前 `step`、最近 3 次评分）、狗的口令表。输出：有序的"回答块"列表与 `cited_content_ids`。

**选哪些条目**（按此顺序，去重）：
1. 上下文技能（课程内提问）或上下文问题行为（诊断后追问），如有。
2. 关键词得分 > 0 的条目，按现有检索排序取前 2 个。
3. 合计最多 3 个条目。

**每类条目展示哪些字段**（全部是内容库原文，不截断、不改写、不拼接成句）：

| 条目 | 展示内容 |
|---|---|
| 技能 | 名称；`tutorial.summary`；`tutorial.success_criteria`；`tutorial.common_mistakes` 全部条目；`scoring_hint`。附"看教程"入口，跳技能详情页 |
| 技能且为上下文技能、带当前步骤 | 在上面内容之前，先展示正在跟练的那份脚本里该步骤的 `instruction` 原文 |
| 问题行为 | 只展示名称，附"开始诊断"按钮进入该问题的诊断树。**不展示任何 solution**，方案只能经诊断到达，以保证 `escalate_if` 一定随方案出现 |

**评分联动**（AI-2 要求用到最近评分）：上下文技能最近 2 次评分都是"没做到"，且该技能 `downgrade_to` 非空 → 在末尾加一个块，指向降级技能（名称取内容库，附跳转）。与 WP-6 降级规则同源。

**口令**：展示技能时若该狗的口令表里有这条技能，显示口令词与手势（取自 `DogCue`，不是 `default_cue`）。

### 16.3 无命中与课程内库外问题（裁定交接单"需要 Fable 决策"第 9 条）

| 情形 | 结果 |
|---|---|
| 无上下文，关键词最高分为 0 | `guard_no_hit`，固定话术，同现状 |
| 有上下文，关键词最高分 > 0 | 正常直出 |
| 有上下文，关键词最高分为 0 | 只直出上下文条目，`kind = normal`，并在末尾追加固定一句：`如果问的不是这个技能，内容库暂时没有覆盖，建议咨询专业训犬师。` |

第三种情形的理由：课程内的"它老是做不好怎么办"这类问法没有关键词但问的就是当前技能，不能一律判无命中；而真正的库外问题此时拿到的也只是当前技能原文加一句提示，不产生任何库外内容。

### 16.4 模板文案

允许写在 Dart 里的只有：字段标签（如"成功标准""常见错误""评分参考"）、引导语、两句固定话术、16.3 的追加句、降级块的引导语。引导语里可以代入内容库的**名称**，不能出现任何步骤、口令、方法描述。打回条件"系统提示模板不含技能文案"的单测同样套用到这些模板字符串上。

### 16.5 存储与展示

- `AiMessage.kind` 仍用 `normal`；`cited_content_ids` 为实际展示的条目 ID，顺序同展示顺序。
- `AiMessage.content` 存展示时的纯文本快照，保证内容库升级后历史对话不变。
- 对话页的回答按块渲染，"参考内容"折叠区保留（AI-6）。
- 历史消息不再影响回答，同一问题在同一上下文下输出恒定。

### 16.6 测试要求（取代第 10 节中与模型相关的部分）

1. `tests/ai_boundary/` 90 题在 `library` 模式下全过：库内 30 题 `kind = normal`、`cited_content_ids` 含 `expect_ids` 之一；库外 30 题 `guard_no_hit`；健康 30 题 `guard_health`。**三组的模型调用次数都断言为 0。**

3. `model_should_refuse.yaml` 10 题在 `library` 模式下的期望改为：通过原文性测试即可（它们会命中相关技能并展示原文，这不算越界）。该文件的用途说明由 Fable 另行更新，Opus 不改 `tests/` 下的题目文件。
