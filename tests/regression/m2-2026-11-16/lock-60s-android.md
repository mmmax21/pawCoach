# M2 后台计时 / 锁屏实测（Android 模拟器）

环境：`puppy_pixel`，Pixel 6，API 35 arm64，软件渲染，debug 包，`emulator-5554`。
方法：电源键灭屏（`mWakefulness=Dozing`）→ 真实等待 → `keyevent 224` 唤醒。
数据来自 App 内置的带绝对时间戳的诊断日志（`TRAIN ...` / `TTS ...`），不是估算。

## 第一轮：保底任务（mini_script，5 步）

| 事件 | 设备时间 | 说明 |
|---|---|---|
| 开始跟练（第 1 步） | 18:05:44.774 | 之后每步 `stepStartedAt` 在此基础上累加 |
| 灭屏 | 18:06:25.804 | 第 2 步（60 秒）进行中 |
| 第 3 步 ENTER（灭屏中） | 18:06:54.860 | 理论边界 18:06:54.774，晚 86 ms |
| TTS 朗读"下一步"（灭屏中） | 18:06:54.864 | 紧接着 `TTS start` 18:06:54.900，发声 |
| 第 4 步 ENTER（灭屏中） | 18:07:24.850 | 理论边界 18:07:24.774，晚 76 ms |
| TTS 朗读"下一步"（灭屏中） | 18:07:24.854 | `TTS start` 18:07:24.884 |
| 唤醒（`keyevent 224`） | 18:07:41.5 | |
| 唤醒后第一次前台 tick | 18:07:44.223 | 剩余 20552 ms；理论 40000 − (44223 − 24774) = 20551 ms，误差 1 ms |

灭屏时长约 76 秒（18:06:25.8 → 18:07:41.5），灭屏期间朗读了 2 次"下一步"。
解锁后截图读数 17；截图命令落后日志约 3-4 秒（软件渲染下 screencap 慢），按绝对时间推算同一时刻剩余约 17 秒，吻合。精度依据以日志为准，不以截图为准。
灭屏期间前台服务保持：`isForeground=true types=0x00000002`（mediaPlayback），通知 `category=transport actions=2`（暂停 / 下一步）。

灭屏时长约 85 秒（19:36:20.3 → 19:37:45.3），灭屏期间朗读了 1 次"下一步"。解锁后截图读数 14，截图同样落后日志数秒，按绝对时间推算吻合。

## 结论

- 计时全程由绝对时间差值计算，Dart `Timer` 只负责叫醒状态机。灭屏中 Timer 是否被冻结不影响结果：步骤切换最晚比理论边界晚 86 ms（灭屏中），唤醒后的剩余秒数与理论值差 < 1 ms。
- 简报第 6 节验收标准"锁屏 60 秒后解锁，误差 ≤2 秒，期间 TTS 至少朗读一次'下一步'"：两轮都满足，灭屏期间分别朗读了 2 次和 1 次"下一步"。
- 第一次朗读有冷启动延迟：首次 `speak` 到 `TTS start` 约 4 秒（模拟器上 Google TTS 引擎首次绑定），之后每次 < 100 ms。真机待测。
